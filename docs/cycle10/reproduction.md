# Cycle 10 reproduction and interfaces

The registered inputs and acquisition receipts are bundled under [`artifacts/cycle10/sources`](../../artifacts/cycle10/sources/). Exact dataset replay uses those original bytes and receipts. Re-downloading publisher pages can change acquisition timestamps or license-page hashes, so a new acquisition is a new provenance record rather than an identical manifest.

The source, runtime and model identities are recorded in the [baseline manifest](../../artifacts/cycle10/baseline/manifest.json), [final implementation verification](../../artifacts/cycle10/verification.json), and [clean-study receipt](../../artifacts/cycle10/current/verified.json). The current receipt identifies the exact fresh-bootstrap receipt used for its checkout. The initial independent bootstrap and byte-exact corpus replay are also retained in [`bootstrap/`](../../artifacts/cycle10/bootstrap/).

## Prerequisites and complete reproduction

Use Linux with `uv`, Git, the audited SWI-Prolog 10.0.1 build with Janus/PCRE, and the `zstd` command-line reader. `scripts/bootstrap.sh --dependencies-only` creates Python 3.12.12 with the existing locked Python dependencies and the pinned PeTTa runtime. The optional figure-rendering interpreter needs Matplotlib; the delivered figures use the separately recorded Python/Matplotlib environment. Browser verification uses ProofShot 0.1.0 and its installed Chromium browser. These presentation tools do not enter native inference.

Commit the delivered package and choose four new directories outside the source checkout:

```bash
bash scripts/bootstrap.sh --dependencies-only
.venv/bin/python -m scripts.cycle10_reproduce \
  --out /tmp/pln-chess-cycle10-reproduction \
  --checkout /tmp/pln-chess-cycle10-clean \
  --baseline /tmp/pln-chess-cycle10-original \
  --browser-work /tmp/pln-chess-cycle10-browser \
  --plot-python python3
```

This creates a fresh checkout, virtual environment and runtime; regenerates the corpus; audits overlap; reproduces the original baseline; runs the frozen model and calibration map first; trains the two registered adaptations; runs actual-history, dependence and regression experiments; benchmarks serially; verifies acceptance; exercises APIs/CLI, repeats the tests after acceptance activates the operational default, verifies the browser, and renders reports and figures. Allow several hours for the full native study. Every subprocess writes a command receipt and log. `--skip-browser` explicitly omits browser execution and records that omission; it does not constitute the full visual delivery.

The replay compares model, dataset, native proof and acceptance identities. Every new external-study shard must also match the delivered ordered native-proof hash and static metrics, and both adapted checkpoints must match byte for byte. Wall times, execution timestamps, compression bytes containing measurements, and figure metadata may differ. The original historical artifacts are checked byte for byte and never overwritten. No command pushes Git commits, deploys services, modifies upstream PLN, enables a new native operator or promotes an adapted model.

For a new acquisition, run `.venv/bin/python -m training.cycle10_acquire --out /tmp/new-acquisition` and inspect all publisher/license/checksum receipts before using the result. The exact registered corpus uses the delivered immutable acquisition instead.

## Import and replay supplied history

```bash
.venv/bin/pln-chess history-import-pgn \
  --input /path/to/game.pgn --source 'publisher/game-record' --output /tmp/prepared-game.json
.venv/bin/pln-chess history-replay \
  --input /tmp/prepared-game.json --ply 12 --output /tmp/history.json
.venv/bin/pln-chess inspect \
  --fen 'RESULTING_FEN_FROM_HISTORY' --move 'CANDIDATE_UCI' \
  --checkpoint artifacts/cycle8/model/C8-promotion-relative.json \
  --history /tmp/history.json --mode operational --format json
```

Replace the two uppercase placeholders with the replayed FEN and candidate move. If an imported file contains multiple games, select `--game-id` from its prepared records. `history-replay --game-id ID --ply N` can replay a bundled external game without a new import. Raw event input JSON can instead contain `initial_fen`, `moves`, `source`, `dependence_group`, `confidence`, `initial_trust`, `complete`, `model_version`, `runtime_version`, and `expected_fen`.

A versioned receipt passed to `inspect --history` activates event-backed transport, validates integrity, and rejects a different bound model or runtime. A legacy history JSON retains its existing `--temporal-mode` contract. The receipt does not certify historical legal play. Partial histories and plain FENs retain unavailable history as unknown; trusted initial metadata is an explicit input policy.

```python
from pln_chess.api import external_report, replay_history, explain_move

history = replay_history(
    '7k/5p2/8/6P1/8/8/8/K7 b - - 0 1', ['f7f5'],
    source='supplied-move-record', dependence_group='one-game',
)
result = explain_move(
    history['resulting_fen'], 'g5f6',
    checkpoint='artifacts/cycle8/model/C8-promotion-relative.json',
    temporal_evidence=history, mode='operational',
)
print(result['candidate']['raw_stv'])
print(result['candidate']['proof_status'])
print(external_report('summary')['data']['external-test'])
```

The literal example is a declared demonstration, not a claim that a real game occurred. `pln_chess.cycle10.temporal.native_options` also configures full-position `infer_moves`; `append_events` preserves event IDs and parent receipt lineage. `compare_external_models` / `compare-external` compare the fixed frozen/small/large checkpoints in an explicit mode, optionally with a versioned history receipt. They never change the operational default.
