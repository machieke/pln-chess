# Scheduling and performance

`NativeSession` hashes exact pure native expressions with prerequisite expression identities. It reuses identical native calculations within a grounded batch and, when explicitly retained by its caller, across requests. Every logical node still has its own premise list, target, rule IDs and evidence. Sharing deterministic scalar evaluation does not make observations independent and does not merge evidence groups. Inputs, native outputs and runtime identity remain in the cache key/proof relationship.

The reference schedule executes all logical native nodes. The optimized cold schedule deduplicates identical calculations. The warm schedule can reuse previously obtained raw native outputs. `artifacts/cycle2/benchmark.json` compares all three on the unchanged 214-candidate Cycle 1 game position, including exact equality of TVs, classifications, proof nodes, evidence lineage and rule IDs. No semantic change is credited to scheduler performance. Separately, the historical and reproduced Cycle 1 baseline have different representations; their timings are contextual comparisons, not a scheduler parity claim.

Stage counts are logical native invocations by operator. Cold/warm timings include host sensing, proof assembly and checkpoint version hashing. They are single-run observations on the recorded environment, not robust production latency distributions. Evaluation reports additionally provide position p50/p95/p99. The runtime launches fresh PeTTa subprocesses for uncached batches; persistent interpreter reuse remains unimplemented. Explicit native-node and timeout budgets produce incomplete outcomes. The cache is caller-scoped and unbounded within that session, so long-lived services should impose eviction before retaining it indefinitely.
