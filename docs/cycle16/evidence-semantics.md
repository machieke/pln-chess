# Evidence semantics and policy boundary

The finite encoding works with the existing guard because each supplied
conditional appears once in the successful path. It adds genuine domain
structure: one explicitly authored hypothesis requiring an ordered two-cell
ray and both separate emptiness observations. It does not repair recursive reuse.

| Provenance category | What it records | Cycle 16 treatment |
| --- | --- | --- |
| Rule schema identity | Which supplied declaration is used | One stable `rule_` stamp |
| Learned rule support | Empirical sources behind its parameters | Real source-game `train_` stamps |
| Environmental evidence | Observed state facts | Stable `obs_` occurrences plus host source ancestry |
| Proof application | An occurrence of using a statement | No invented independent-evidence identity |
| Derivation ancestry | Inputs contributing to an intermediate | Native-returned stamp union |

A new application is not a new observation. Two different facts with distinct
occurrence stamps are not thereby statistically independent: they share a board
and source game. Conversely, repeated use of one conditional is not necessarily
the same statistical operation as revising independent estimates of that
conditional. The pinned runtime uses one conservative overlap guard for
statement combination. This study does not declare that policy mathematically
wrong; that would require a specified alternative semantics.

There are three distinct localized outcomes:

1. Recursive extension: both needed premises exist and structurally match, but
   reuse overlaps `rule_extend-empty`; the two-cell result is absent.
2. Supplied finite path: the nested implication consumes distinct observed
   emptiness facts, without reusing a rule identity, and native derivation returns
   the consequence.
3. Learned full chain: real overlapping training ancestry prevents combining
   returned clearance with the matching terminal partial. This remains blocked
   with generous budgets. It is not a missing-target binding failure.

Other failures have different causes: the 24-step run leaves tasks unprocessed;
unknown occupancy supplies no emptiness premise; missing entities invalidate the
query domain; an untrained prior supplies no supported clearance; malformed
native execution is incomplete. No universal stamp explanation is applied.

Nested implications are evaluated through the existing modus ponens truth
function. Numerical success does not establish that currying is equivalent to
a general probabilistic conjunction. The tested strength-one confidence swaps
have equal results, but that restricted observation does not prove commutativity
for uncertain strengths or shared parameters. Training labels here are all
positive after exact conditional admission, so values are support measures under
the assumptions, not calibrated failure probabilities.

Any future generic evidence-policy proposal should specify separate operations
for reusable schema application, uncertain parameter reuse, environmental-source
dependence, revision of estimates, and cyclic derivation. Before implementation
it must define a probabilistic interpretation, state what information is retained
about joint dependence, establish how repeated uncertain parameters propagate,
and show that duplicate delivery and proof cycles cannot manufacture evidence.
Tests must include this recursive counterexample, shared-ancestry learned chains,
diamonds, replay, unequal-confidence premises, false hypotheses, and additional
path lengths. An upstream calculus review and separate authorization are needed.
No alternative policy or prototype has been implemented here.

| Shortcut | Counterexample it would invalidate |
| --- | --- |
| Remove all rule stamps | Repeated uncertain rule use silently appears independent |
| Unique stamp for every firing | A cycle generates unlimited apparently fresh support |
| Ignore training overlap | Two parameters estimated from the same games can double-count evidence |
| Revise repeated observations | Duplicate delivery raises confidence without new information |
| Allow cycles to accumulate confidence | A → B → A strengthens A using only A |
| Replace dependency structure with one Boolean flag | A diamond's shared ancestor and disjoint leaves cannot be distinguished |
