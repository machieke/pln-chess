## Source and environment identities

The outer clean-reproduction driver binds its own hash separately from the frozen child programs it invokes.

The [fresh bootstrap receipt](../../artifacts/cycle14/clean-research/bootstrap/verified.json) binds Python 3.12.12, the dependency lock, fresh virtual environment and fresh native runtime. These are pinned implementations, not permission to substitute current upstream releases.

Use the repository virtual environment, not an unqualified `python` command: this workstation also has a Python 2 executable. Every subprocess receipt records its executable, arguments, source identity, output generation and log. `PLN_CHESS_ROOT` and `PYTHONPATH` point to the intended clean checkout. Output overrides for earlier cycles are removed before current verification.

## What is rebuilt, replayed or supplied

The baseline research run regenerates all 340 immediate labels, 120 temporal labels and 400 native feature artifacts, then refits and evaluates the original research models. It compares 527 artifacts with the delivered Cycle 13 evidence. Baseline legality, its 588 tests, negative/history controls and recoveries are independently executed. The [comparison](../../artifacts/cycle14/baseline/research/comparison.json) distinguishes byte identities from scientific/native proof equivalence.

The initial baseline control invocation stopped because the orchestration omitted a predecessor-receipt file required by the unchanged historical runner. The failure remains in the original command/log generation. The [control completion receipt](../../artifacts/cycle14/baseline/control-completion/verified.json) records supplying the genuine retained Cycle 13 predecessor receipt and freshly executing both control suites against the clean starting source. That historical prerequisite is not counted as a new execution; the new control outputs are independently checked before the baseline receipt closes.

After all 206 native shards completed, the serial host-side aggregate comparison was replaced by three bounded workers using the unchanged full-proof comparator. The [transition receipt](../../artifacts/cycle14/baseline/serial-comparison-interruption.json) records that no native child was active or interrupted. Every comparison was recomputed, including work already done in memory, and [per-shard comparison receipts](../../artifacts/cycle14/baseline/comparison-receipts/) bind exact input bytes. Both the discarded serial work and replacement work remain in CPU accounting. The maintained baseline runner now supplies its predecessor prerequisite and invokes this resumable comparator automatically. Reruns must use a new output generation with the frozen baseline manifest; changing a driver cannot resume an older generation under a different identity.

Current research reproduction rebuilds source partitions, concept cases and temporal/response plans. The complete frozen label generation is an explicit input. Selected raw searches are independently repeated by actor, horizon, label and unresolved-cause strata; the [selected verification receipt](../../artifacts/cycle14/clean-research/selected/verified.json) enumerates them. This is not a claim that every new reference-engine search was repeated. Selection covers verification strata and does not depend on model accuracy.

All 940 immediate and 240 temporal compact feature archives undergo full hash/reachability validation, exact canonical expansion and native expression replay. Every archived native node must be covered by an ordered trace. Pure expression arithmetic may be memoized within an archive, while distinct evidence occurrences remain distinct. Three disjoint deterministic shards stream completed archives; the final [proof receipt](../../artifacts/cycle14/clean-research/proof-replay/verified.json) joins all 1,180 cases. Additional fresh observation construction covers collection, final-test membership and short-branch strata. Complete archive replay and selected fresh extraction are deliberately reported as different checks.

The fresh environment refits all experimental checkpoints and evidence ledgers, repeats development selection and calibration freezing, and regenerates final predictions, factorial contrasts, dependence interventions, reversal/removal fits, concepts and locality controls. It also repeats all ten bounded response panels and both diagnostic archives. The [research comparison](../../artifacts/cycle14/clean-research/comparison.json) lists each compared artifact and method. JSON checkpoints, ledgers and scientific summaries require byte equality. Compressed native records compare canonical content after removing elapsed-time telemetry only. Complete response archives first validate their hashes and summary-root bindings, then compare all native scientific evidence; only validated archive-derived roots, request handles and timing fields are excluded from the corresponding response-summary comparison. Synthetic [verifier controls](../../artifacts/cycle14/verification/response-comparison-controls.json) establish that changed truth values and incorrect root bindings are rejected.

The current legal replay separately executes all 206 shards and compares all 584,112 ordered candidate records with the independently reproduced baseline. Full tests and the 287 negative, 27 history, two recovery and 76 holdout controls run in that same clean source environment. Browser work exercises the frozen production code with delivered experimental models, actual downloads/uploads, mobile and desktop layouts, and durable retrieval across a server restart. CLI verification uses separate processes, not in-process calls presented as restarts.

## Repeating the delivered research check

From the completed delivery checkout, use a new output generation and a new checkout path. This command reads the delivered evidence and creates separate replay receipts; it does not replace the delivered `clean-research` generation:

```bash
.venv/bin/python -u -m scripts.cycle14_reproduce \
  --out artifacts/cycle14 \
  --checkout /tmp/pln-chess-c14-replay \
  --commit de08667d3b6962b52797a968d8df0a949649aa6d \
  --generation clean-research-repeat
```

The command binds the full frozen verification commit. Dependencies/runtime are freshly bootstrapped when the new generation has no bootstrap receipt. Native corpus replay, selected searches and model refits are substantial jobs. A new repetition does not reuse the delivered replay receipts. The command logs under the generation record each stage, failed attempts and successful resumes. The delivered run schedules its fresh Stockfish compilation with [one worker](../../artifacts/cycle14/clean-research/reference-bootstrap/one-worker-build.json), using the already hash-verified release archive as a source cache. This changes compiler parallelism only; the resulting binary must be byte-identical to the registered teacher. A new unscheduled replay uses the existing four-worker bootstrap.

For an individual study, inspect the matching command in [the primary pipeline](../../artifacts/cycle14/pipeline/commands/) or [clean replay commands](../../artifacts/cycle14/clean-research/commands/). Those records bind the exact inputs and driver hashes. Re-running a changed driver into an existing scientific generation is rejected; preserve the old generation and choose a new one. Interrupted earlier feature and proof-stream attempts remain in the evidence inventory. The 109 completed earlier feature cases were all compared with the replacement serialization generation before selecting it.

The dense response study initially exceeded the production serializer's two-million expanded-object occurrence budget. The failed command and first two completed panels remain under `bounded-responses.attempt-1` and `responses-attempt-1`. The retry uses [an explicit offline budget](../../artifacts/cycle14/verification/offline-archive-budget.json) and retains exact archive encoding, evidence multiplicity and native values. Interactive export still has its original limit. All ten response plans are rerun, including those that completed earlier, with no data, threshold or model change.

The [sparse audit bootstrap](../../artifacts/cycle14/clean-research/bootstrap-audit/verified.json) materializes all required production, research, source-data and checkpoint files while omitting unrelated historical legal-output copies. Its first setup attempt used a `git sparse-checkout set` flag unsupported by Git 2.25.1, omitted root dependency files, and stopped before installing dependencies or the native runtime. The retained retry initializes cone mode explicitly and completes a fresh environment. It inherits the already independently compiled teacher binary byte-identically; [the build lineage](../../artifacts/cycle14/clean-research/reference-build-lineage.json) does not claim a second compilation. The dense archive regression also runs in this fresh checkout, with [its own test receipt](../../artifacts/cycle14/verification/offline-archive-clean.xml), separately from the 639-test suite on the production verification checkout.

Benchmark repetitions run after owned corpus, legal, replay and UI verification jobs have finished. The [workload census](../../artifacts/cycle14/performance/workloads.json) records the process check, host load and fixed C13 workload identities. Each workload/arm/repetition has its own process and cold/warm measurements, with twenty repetitions and alternating arm order. Timing values are not expected to reproduce byte-for-byte. Native/evidence identities are. Parent and child RSS maxima remain separate, and sample p99 is not a service guarantee. See [performance](performance.md) for latency, archive cost and memory distributions.

## Resource accounting and limits

The registration sets 128 research CPU hours, 24 hours per stage, six billion reference nodes, one million interpreter launches, twelve concurrent owned workers, 40 GiB new retained artifacts and 64 GiB temporary checkouts. The [resource ledger](../../artifacts/cycle14/resources.json) records measured CPU receipts, reference nodes, native launches where instrumented, retained artifact sizes and temporary checkout usage. Reused labels are counted once, and cumulative MultiPV nodes are not added once per candidate. Model loading, native execution, serialization, audit export and retrieval have distinct benchmark fields.

Continuous process accounting was not installed at the start of the cycle. Total early CPU use, interpreter launches, transient generated bytes and the complete historical concurrency peak cannot be reconstructed exactly. Reported CPU and launch totals are therefore lower bounds; missing counters are not zeros and global compliance with those ceilings is unverified. Six baseline terminal-endpoint analyses also returned no node counter: they are listed separately rather than assigned a fabricated zero. The available reported-node sum is checked against its ceiling, while the exact complete reference-node total remains unverified. Retained bytes are a snapshot, not total filesystem write volume; retained-storage ceilings are checked from recorded evidence. These are explicit resource-measurement shortfalls in C14-19, not waivers of any legal, native-proof or scientific preservation gate.

The [final inventory](../../artifacts/cycle14/delivery/artifact-inventory.json) hashes retained successful, failed and interrupted evidence separately from the source-bound passing gates. Its two inventory/audit files exclude their own circular hashes. The ending local commit and clean worktree are reported after the final evidence commit; no remote write is part of reproduction or delivery.


The full native-boundary audit and independent research refit run concurrently once all scientific inputs and selected replay cases are closed. [The bounded schedule](../../artifacts/cycle14/verification/early-clean-research-policy.json) allows four legal workers, one control worker, one audit worker and one refit worker. After controls finish, two cached proof-partition validators may briefly replace the control worker, for at most eight owned verification workers. An exclusive per-generation lock prevents duplicate refits. The ordinary final coordinator revalidates the completed research source, frozen inputs, comparison hashes and output hashes after the audit passes. Benchmarking still waits for both verifiers and all owned compute jobs to exit.

The first clean response comparison stopped because durable request handles bind the full timed summary and archive root. Independent runs therefore have different valid handles. The failed manual and coordinator receipts remain under `verification/commands/*clean-research.attempt-1.json`. The [binding audit](../../artifacts/cycle14/verification/response-handle-bindings.json) recomputes all 24 handles from their registered requests using the production identity function; only those validated handles are excluded from scientific equality. Five [comparison controls](../../artifacts/cycle14/verification/response-binding-controls.xml) accept valid execution differences and reject changed truth values, roots, handles or request history. The final comparison reruns against the complete immutable outputs; this verifier correction changes no production source, observations, model, prediction or threshold.
